# 成片隐私扫描

口播在家门口、街边拍，背景里的路名牌、门牌号一闪而过，按颜色找会漏掉，所以写了这个：逐帧识别画面里的文字，再搜路名、门牌、电话。

- 形态：命令行（只能在 macOS 上跑，用的是系统自带的 Vision 文字识别）
- 状态：在用
- 最后改动：2026-10-24

## 怎么用

```bash
bash scan.sh 成片.mp4        # 默认每秒抽 10 帧
bash scan.sh 成片.mp4 2      # 每秒 2 帧，快很多，适合先过一遍
```

第一次运行会自动编译 `ocr_scan`（要装 Xcode 命令行工具，`xcode-select --install`）。

屏幕上会打出命中的帧，比如：

```
f00001.jpg 南京西路1234号@96,410,380,60
== 上面这些帧可能露了位置信息，回去看一眼，需要就补遮。
```

`@` 后面是这段字在画面里的位置：左、上、宽、高，单位是像素，左上角为原点。帧号除以抽帧速度就是秒数，比如每秒 10 帧时 f00150 大约在第 15 秒。全部识别结果写在视频旁边的 `成片.ocr.txt`。

想换搜的词，用环境变量：

```bash
OCR_PATTERN='路|街|电话|你的小区名' bash scan.sh 成片.mp4
```

## 依赖

- macOS、Xcode 命令行工具（swiftc）
- ffmpeg（`brew install ffmpeg`）

## 风险与边界

- 只读视频，不改原文件；抽出来的帧放在临时目录，跑完就删。
- 它只认字，不认人脸、车牌形状、楼的样子。没搜到不等于安全，只是少了一类最容易漏的。
- 会有误报：「弄」「路」这些字在字幕里也常见（比如「弄错了」），命中了要自己看一眼。
- 字太小、太斜、被挡住一半的认不出来。每秒抽帧越多越不容易漏，也越慢：两分钟的竖屏视频，每秒 2 帧在 M 系列芯片上大约 40 秒。

## 迁移说明

原来在本机口播项目里，2026-10-09 起每支成片交付前都跑一遍（那天发现按颜色扫漏了一块大路名牌）。2026-10-24 搬来，搬的时候改了两处：坐标原来写死成 1080×1920，现在按每一帧的实际尺寸算；加了 `scan.sh`，把抽帧、识别、搜词串成一条命令，并修掉了帧文件名里的数字被当成命中的问题。搬来后用一支真成片重新跑过。
