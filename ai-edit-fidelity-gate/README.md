# AI 改稿保真闸

让 AI 帮忙改稿，它常常悄悄改掉数字、删掉链接、打乱小标题顺序，肉眼一段段核对太累，所以写了这个自动比对脚本。

- 形态：Python 命令行
- 状态：在用
- 最后改动：2026-09-25

## 怎么用

```bash
python3 fidelity_check.py --before a.md --after b.md
```

`--before` 是改稿前的 Markdown，`--after` 是改稿后的。跑完把「硬伤」和「告警」打到 stderr，退出码 0 表示通过（可能带告警），1 表示不通过（有硬伤）。可以直接接进任何改稿流程当卡点：

```bash
python3 fidelity_check.py --before draft.md --after rewritten.md || echo "改稿有问题，别直接用"
```

核对四样：
1. **URL 集合**：改稿前后链接是否一致（丢了/多了都算硬伤）。
2. **阿拉伯数字集合**：数字是否一致（丢了/多了都算硬伤）。
3. **中文数字＋量词**（「九分钟」「三年」「五种」）：输出比输入多出来的算硬伤（疑似编造），输入有输出没有的只告警（可能是被换成了阿拉伯数字，那会在第 2 项被抓到）。
4. **H2 结构**：标题数量要一致，且每个标题下面的正文要跟输入里同一序号标题下的正文是同一段——按字符二元组相似度找「这段正文最像输入的哪一节」，序号对不上就判定为错位（常见于 AI 重写时插入了新标题，导致后面所有标题整体下移一格）。

## 依赖

无第三方依赖，只用 Python 标准库。不调用任何 API，纯本地文本比对。

## 风险与边界

不删改任何文件，只读两个输入文件、打印结果。这是一个启发式工具，不是语义理解：
- URL/数字集合比对是精确匹配，改稿时把数字从「9」写成「9.0」也会被判定为「丢了/多了」。
- 中文数字量词的识别是一个正则表达式，覆盖了常见量词（分钟/小时/年/种/个/条…），不是详尽列表，罕见量词可能漏抓。
- H2 结构闸假设文章用 `##` 分节；不用二级标题或标题层级更深的文章，这条检查不生效（会跳过，不报错）。
- 这是「有没有可疑改动」的机械信号，不是「改得好不好」的判断，通过了也建议再过一遍冷读。
