# Apple Watch 录音拼接

Apple Watch 录了好几段语音备忘录，中间夹杂大段环境噪音或空白，一段段听、一段段剪太麻烦，所以写了这个：用 Whisper 识别出「真的在说话」的片段，自动掐掉空白，再按时间顺序拼成一个文件。

- 形态：Python 命令行
- 状态：已停
- 最后改动：2026-03-07

## 怎么用

```bash
python3 merge_recordings.py /path/to/录音文件夹
```

不带参数运行会交互式提示输入文件夹路径。启动时会依次问：选 Whisper 模型大小（tiny/base/small/medium/large，默认 base）、选语言（默认中文）。处理完在当前目录生成 `merged_recording_<时间戳>.m4a`（拼接后的音频）和同名 `.txt`（每段内容的转写文本，带时间戳和来源文件名）。

首次运行会自动 `pip install` 缺的依赖（`pydub`、`openai-whisper`、`numpy`、`torch`），也可以先手动装好。

如果拼接结果不对劲（比如该有声音的地方被当成空白切掉了），先用 `diagnose_audio.py` 看看问题出在哪：

```bash
python3 diagnose_audio.py /path/to/某段录音.m4a
```

它会按 30 秒一段分析音量和动态范围，标出哪些是静音、单调噪音（风扇/摩擦声）、疑似语音，并列出检测到的非静音片段。

## 依赖

- Python 3
- `pydub`、`openai-whisper`、`numpy`、`torch`（首次运行自动安装）
- 系统需要有 `ffmpeg`（`pydub` 依赖它做格式转换）

## 风险与边界

- 只生成新的合并文件和转写文本，不会删除或修改原始录音。
- Whisper 转写在本机跑，不上传音频；base 模型速度和准确度是个折中，效果不满意可以换更大的模型（但会慢很多）。
- 判断「有效片段」的逻辑比较简单（按静音间隔、纯语气词过滤），可能会把小声说话的内容当噪音跳过，重要录音建议跑完后对照 `diagnose_audio.py` 的结果检查一遍。
- 首次运行会自动装依赖包（含体积较大的 `torch`），网络不好或磁盘紧张的时候留意一下。
