# 争议议题分析团队（Critical Debate Team）

> Agent Teams 分析线的第一个验证项目。
> 用对抗性多角色架构，替代单 Agent 的"两边各打五十大板"式分析。

---

## 快速上手

### 1. 进入项目目录

```bash
cd critical-debate-team
```

### 2. 启动分析

在 Claude Code 中运行：

```
请分析以下争议议题：[你的议题]
```

Claude Code 会自动读取 CLAUDE.md，按照工作流调度三个角色。

### 3. 或者使用模板启动

```
请读取 templates/debate-brief.md，我要填写一个新的分析任务。
```

## 设计原理

### 为什么不用单 Agent？

单 Agent 分析争议议题时有一个结构性缺陷：它在同一个上下文窗口里先写完正方论据，然后写反方时已经被自己的正方文字锚定了。结果就是"看似平衡，实则平庸"——两边各打五十大板，没有真正的张力。

### 三角色如何解决这个问题？

- **立场 A 辩护者**和**立场 B 辩护者**在各自独立的上下文里全力为一方辩护，不需要顾及平衡
- **哲学审计员**从一开始就旁听辩论过程，但不参与立场辩护，专门揭示双方的隐含假设和逻辑漏洞
- Lead Agent 负责判断辩论何时收敛，以及综合三方产出

### 关键设计决策

1. 审计员全程旁听，不是辩完才介入——这样能捕捉辩论过程中的逻辑滑动
2. 两个辩护者通过 teammate messaging 互相质疑，不是各自独白
3. 最终产出不追求"结论"，追求"让读者看清张力结构"

## 与生产线的串联

这个团队的产出可以直接写入播客生产团队的 `context/ammo-library.md`，作为选题弹药。

具体用法：当你要做一期涉及争议性话题的播客时，先用这个团队跑一轮分析，把产出喂给策略师。
