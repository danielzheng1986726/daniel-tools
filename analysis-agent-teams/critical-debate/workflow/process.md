# 工作流定义：三阶段争议分析

## 全局规则

- 每个阶段有明确的完成条件，Lead Agent 判断是否满足后才推进到下一阶段
- 审计员全程在线旁听，但只在阶段 3 正式发言
- 总流程控制在 3-4 轮交互内完成（避免无限辩论）

---

## 阶段 1：独立建构

### 触发条件
Lead Agent 完成议题解析和立场分配。

### 任务分配

| 角色 | 任务 | 产出 |
|------|------|------|
| Advocate A | 为立场 A 构建最强论证 | 独立论证文档（含核心主张、论证结构、价值观基础、最强一击） |
| Advocate B | 为立场 B 构建最强论证 | 独立论证文档（同上格式） |
| Auditor | 旁听两份论证，开始记录隐含假设和概念歧义 | 内部笔记（不对外输出） |

### 并行/串行
Advocate A 和 Advocate B **并行执行**。两者之间不互相看到对方的产出。

### 完成条件
Lead Agent 检查两份论证：
- 是否有具体论据（不是空泛口号）
- 是否形成了真正的张力（不是在说同一件事）
- 是否明确了各自的前提条件

如果不满足，要求对应角色补充后再进入阶段 2。

---

## 阶段 2：交叉质疑

### 触发条件
阶段 1 完成条件满足。

### 任务分配

Lead Agent 将 Advocate A 的论证发送给 Advocate B，反之亦然。

| 轮次 | 动作 |
|------|------|
| 第 1 轮 | A 攻击 B 的论证 + B 攻击 A 的论证（并行） |
| 第 2 轮 | A 回应 B 的攻击 + B 回应 A 的攻击（并行） |
| 第 3 轮（可选） | 如果 Lead 判断还有未触及的核心分歧，再进行一轮 |

Auditor 全程旁听所有交叉质疑内容，持续更新内部笔记。

### 每轮质疑的格式要求
- 300-500 字
- 必须攻击对方的最强论点（不许打稻草人）
- 如果对方有好论据，先承认再解释为什么不足以推翻己方立场

### 收敛判断（Lead Agent 执行）

在第 2 轮结束后，Lead Agent 评估：

1. **核心分歧是否已暴露**：双方是否已经触及了真正的分歧点（价值观层面、事实层面、预测层面），还是仍在表面细节上打转？
2. **新维度是否出现**：交叉质疑过程中，是否出现了独立建构阶段没有的新视角或新论据？
3. **边际价值判断**：继续辩论是否还能产生新洞察？还是开始重复已有论点？

如果核心分歧已暴露且边际价值递减 → 进入阶段 3。
如果核心分歧尚未充分暴露 → 进行第 3 轮，但第 3 轮后必须进入阶段 3（硬性上限）。

---

## 阶段 3：综合产出

### 触发条件
阶段 2 收敛判断完成。

### 任务分配

| 顺序 | 角色 | 任务 | 产出 |
|------|------|------|------|
| 先 | Auditor | 基于全程旁听记录，出具审计报告 | 审计报告（五部分结构，详见 auditor.md） |
| 后 | Lead Agent | 综合两方论证 + 审计报告，生成最终分析 | 最终分析文档 |

### Auditor 和 Lead 的分工

**Auditor 负责**：
- 分歧本质诊断
- 隐含假设清单
- 逻辑质量评估
- 盲区与未探索维度
- 条件性判断框架

**Lead Agent 负责**：
- 将审计报告和两方论证整合成一份连贯的、可读性强的最终分析
- 确保最终产出满足 context/analysis-principles.md 中的质量标准
- 添加必要的背景说明和术语解释
- 控制总篇幅（最终产出建议 2000-3000 字，视议题复杂度可调）

### 最终产出结构

```
# [议题名称] — 争议分析

## 议题背景
（Lead Agent 撰写，200 字以内）

## 立场 A：[立场名称]
### 核心论证
（基于 Advocate A 的最终版论证，提炼精华。必须包含至少一处对 B 最强攻击的正面回应。）
### 最强一击
（Advocate A 的最强单句论证）

## 立场 B：[立场名称]
### 核心论证
（基于 Advocate B 的最终版论证，提炼精华。必须包含至少一处对 A 最强攻击的正面回应。）
### 最强一击
（Advocate B 的最强单句论证）

## 张力结构
（基于 Auditor 的审计报告第一部分和第二部分）
- 分歧的本质是什么
- 双方共享的隐含假设
- 各自的盲区

## 条件性判断
（基于 Auditor 的审计报告第五部分）
- 什么条件下 A 更有说服力
- 什么条件下 B 更站得住脚
- 哪些现实变化可能改变判断

## 未探索的维度
（基于 Auditor 的审计报告第四部分）
```

### 完成条件

Lead Agent 对最终产出做质量自检：
- [ ] 两方论证是否有真正的张力
- [ ] 是否揭示了至少一个双方都没意识到的隐含假设
- [ ] 是否避免了"各打五十大板"的平庸结论
- [ ] 条件性判断框架是否具体到可以用于实际决策
- [ ] 分析是否具体到可以被反驳

通过自检后，写入 output/ 目录。
