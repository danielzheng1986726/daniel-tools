# 工作流定义：三阶段因果分析

## 全局规则

- 两个分析者在阶段 1 互不可见，确保认知多样性
- 阶段 2 的交叉验证是双向的，不是单向审查
- Lead Agent 在阶段 3 负责合并、去重、评估、排序

---

## 阶段 1：独立建构

### 触发条件
Lead Agent 完成现象解析和分析范围确认。

### 任务分配

| 角色 | 任务 | 产出 |
|------|------|------|
| 主流解释者 | 从成熟理论和证据出发，生成 5-8 个原因 | 原因清单（含因果机制、证据基础、确信度） |
| 边缘探索者 | 绕开显而易见的解释，生成 4-6 个非常规原因 | 原因清单（含排除声明、认知来源、因果机制、价值声明） |

### 并行执行
两个分析者**并行**，互不可见对方产出。

### 完成条件

Lead Agent 检查：
- 主流解释者的清单是否覆盖了该领域最常被提及的解释
- 边缘探索者是否完成了排除步骤，且清单与主流解释者的重叠率低于 30%
- 每个原因是否都有完整的因果链（不是只有标签）

重叠率过高 → 要求边缘探索者重做。

---

## 阶段 2：交叉验证

### 触发条件
阶段 1 完成条件满足。

### 任务分配

Lead Agent 将主流解释者的清单发给边缘探索者，反之亦然。

| 角色 | 任务 |
|------|------|
| 主流解释者 | 对边缘探索者的每个原因标注 ✓/？/＋ |
| 边缘探索者 | 对主流解释者的每个原因标注 ✓/？/＋ |

标注格式：
- ✓ 支持：一句话说明额外证据或逻辑支撑
- ？质疑：具体指出逻辑漏洞或反面证据
- ＋ 补充：简述延伸出的新因果链

### 完成条件

两方都完成标注。Lead Agent 特别关注：
- 边缘探索者提出且主流解释者标注"✓"的原因（高价值发现）
- 两方互相标注"？"的原因（争议点，需要在最终报告中说明）

---

## 阶段 3：合并评估

### Lead Agent 执行以下步骤

**步骤 1：合并去重**
- 将两份清单中实质相同的原因合并
- 标注每个原因的来源：[主流] / [边缘] / [共识]

**步骤 2：交叉验证结果整合**
- 对每个原因附上对方的标注（✓/？/＋）
- 特别标注"高价值发现"（边缘提出 + 主流支持）

**步骤 3：按评估框架打分**
详见 context/evaluation-criteria.md。六个维度打分，生成综合评分。

**步骤 4：因果网络绘制**
用自然语言描述主要原因之间的关系：
- 哪些原因互相强化（正反馈）
- 哪些原因互相矛盾（不可能同时成立）
- 哪些原因有条件依赖（A 成立的前提是 B 也成立）

**步骤 5：生成最终报告**

### 最终产出结构

```
# [现象名称] — 系统性因果分析

## 现象描述
（200 字以内，含分析范围界定）

## 因果清单（按可信度排序）

### 第一梯队：高可信度
（综合评分最高的 2-3 个原因，每个含因果机制、证据、确信度）

### 第二梯队：中等可信度
（综合评分中等的原因）

### 第三梯队：待验证假说
（逻辑合理但证据不足的原因，每个附验证方向）

### 🔍 高价值发现
（边缘探索者提出且主流解释者支持的原因，单独标出）

## 因果网络
（原因之间的相互关系：强化、矛盾、条件依赖）

## 验证建议
（针对最重要的待验证原因，提出具体的数据收集或研究方向）

## 分析局限
（本次分析的范围限制、信息不足之处、可能的盲区）
```

### 质量自检

- [ ] 最终清单中边缘探索者独有的原因占比 ≥ 30%
- [ ] 每个原因都有完整因果链
- [ ] 因果网络部分揭示了至少一个原因间的非线性关系
- [ ] "高价值发现"部分非空（如果为空，需反思边缘探索者是否真正跳出了框架）
- [ ] 验证建议具体到可执行

产出写入 output/ 目录。
