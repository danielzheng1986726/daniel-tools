# 工作流定义：研究报告审计

## 全局规则

- Lead Agent 先做快速体检（Quick-Scan），再决定是否进入深度审计
- 两个审查者在阶段 1 并行、互不可见
- 阶段 2 的对照质证确保两种视角充分碰撞
- 最终产出必须保留对比痕迹

---

## 阶段 0：快速体检（Lead Agent 执行）

收到材料后，Lead 先做 Quick-Scan Checklist：

| # | 检查项 | ✓/? |
|---|--------|-----|
| 1 | 可追溯数据来源 | |
| 2 | 合理的基期数字 | |
| 3 | 明示的增长逻辑或模型 | |
| 4 | 至少 2 个独立第三方预测与其量级相近 | |
| 5 | 提及风险或情景分析 | |

- 🟥 0-1✓：告知用户"此材料信息密度较低，建议仅作为话题线索"。用户可要求继续。
- 🟡 2-3✓ 或 🟢 4-5✓：自动进入阶段 1。

同时判断材料类型，调整审查侧重：
- **研究报告/学术论文** → 侧重：数据来源、采样方法、统计分析、因果推断
- **市场预测/行业报告** → 侧重：预测模型、CAGR 合理性、TAM/SAM/SOM 区分、情景分析

---

## 阶段 1：并行审查

### 任务分配

| 角色 | 任务 | 产出 |
|------|------|------|
| 魔鬼代言人 | 从最可疑处切入，找漏洞 | 审查报告（含严重/中度/轻度问题清单、缺失信息、替代结论） |
| 善意诠释者 | 从最强证据处切入，找价值 | 审查报告（含核心价值、最强证据链、最合理结论、使用建议） |

### 并行执行
两个审查者**并行**，互不可见对方产出。

### 完成条件

Lead Agent 检查：
- 魔鬼代言人是否找到至少 2 个**具体的**质疑点（含位置和影响评估）
- 善意诠释者是否识别了至少 1 个有真正价值的发现
- 两方是否都从具体文本/数据出发（而非泛泛评论）

---

## 阶段 2：对照质证

### 触发条件
阶段 1 完成条件满足。

### 任务分配

Lead Agent 将魔鬼代言人的报告发给善意诠释者，反之亦然。

| 角色 | 任务 |
|------|------|
| 魔鬼代言人 | 对善意诠释者识别的"价值点"进行检验：这些价值点是否建立在有问题的数据之上？ |
| 善意诠释者 | 对魔鬼代言人标记的"严重问题"进行评估：这些问题是否真的动摇了核心结论？ |

每方的回应控制在 300-500 字。

### 完成条件

两方都完成回应。Lead 特别关注：
- 是否有任何发现让对方改变了判断（这是最有价值的信号）
- 两方对同一个数据点的解读分歧（这通常是报告的关键不确定性所在）

---

## 阶段 3：综合裁决

### Lead Agent 执行

**步骤 1：可信度评分**

按 context/audit-dimensions.md 的六个维度打分，生成总分和灯色。

**步骤 2：生成对比报告**

### 最终产出结构

```
# [报告名称] — 审计报告

## Quick-Scan 结果
（五项检查 + 灯色）

## 一句话判断
（总分 + 可信度等级 + 一句话概括）

## 报告最大的优点
（基于善意诠释者的发现，附魔鬼代言人的检验意见）

## 报告最大的漏洞
（基于魔鬼代言人的发现，附善意诠释者的评估意见）

## 可信度评分明细

| 维度 | 评分 | 魔鬼代言人视角 | 善意诠释者视角 |
|------|------|---------------|---------------|
| ... | ... | ... | ... |

## 结论校准
- 报告原始结论：[摘要]
- 数据约束下的最合理结论：[善意诠释者版本]
- 如果报告结论错了，最可能的替代结论：[魔鬼代言人版本]

## 使用建议
- 这份报告适合作为：[决策依据 / 方向性参考 / 话题线索 / 不建议使用]
- 如果要基于此报告做决策，需要额外验证：[具体验证方向]

## 二次验证清单
[3-5 个具体的、可执行的验证动作]
```

### 质量自检

- [ ] Quick-Scan 结果完整
- [ ] 每个维度的评分都有两方视角的支撑
- [ ] "报告最大的优点"和"最大的漏洞"都附有对方的检验/评估意见（对比痕迹）
- [ ] 结论校准部分呈现了三个版本的结论（原始/最合理/替代）
- [ ] 使用建议具体到可以直接指导决策
- [ ] 二次验证清单可执行

产出写入 output/ 目录。
